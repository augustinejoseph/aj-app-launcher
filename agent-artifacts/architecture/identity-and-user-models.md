# Identity and user models
Each app owns its internal user IDs, permissions, provisioning and data. The logical identity key is (provider, verified provider subject); email is contact and allowlist metadata, not a replacement primary key. Health's Google-specific table has a unique subject and unique user_id, retaining its existing text user ID and all relationships. No UUID conversion or user-table rebuild is warranted. Existing profile/preferences and health data remain separate from linkage. Journal's current schema stays unchanged. Future Django apps should choose their user model before first production migration; no Django infrastructure is introduced here.
